# 请求重建规则

目标是让普通 Pi 扩展压缩实际请求，同时保留公开 hook 内容和完整工具批次。

源 occurrence 是 hook 前输入数组中的一次出现，保存对象引用及当时 JSON 字节。canonical projection 在 hook 完成、确定需要压缩后读取，保存压缩前 entry ID 与消息。重建优先使用 hook 前源快照字节，新增 canonical 对象再序列化。新 projection 的 entry ID 决定 canonical occurrence 是否被摘要。同字节组只有全部来源都被摘要时，才允许把对应输入标为可移除。跨截断重复保守保留。

真实安装的 ExtensionRunner.emitContext 会先 structuredClone 输入。普通公开 hook 通常进入字节组分支，因此 duplicate 会保守保留两份。对象身份只在实际仍相同的情况下可用，不能假设经过宿主克隆后仍保留。

先按对象引用匹配 hook 输出。修改过的对象消耗对应来源但保留内容。重复对象只有出现次数一致且来源处置一致时可移除。未匹配项再按字节组匹配。若任一未匹配的非 system 输出含新内容，修改项可能消耗任意旧来源，此时整段字节映射不确定，全部保留。这避免“修改旧消息并添加其原内容克隆”被错误等量配对。没有此类不确定项时，只有未认领来源和输出数量完全一致且来源全部可移除时才删除。额外克隆、删除后数量不一致及跨截断歧义保留。完全克隆、等量、内容不变的数组被定义为原 occurrence 的等价表示。公开接口没有来源标签，无法区分删除后再创建同字节、同数量替身；保守策略不声称能恢复不可观察的作者意图。

hook 输出顺序是唯一输出顺序，不从 projection 补回 recent 消息。只插入本轮新 compaction entry 的摘要，保留 hook 的 system。原生 no-work 不插入摘要。hook 不重跑。hook 前快照使数组和内容的原地修改都可检测。未触发压缩时不额外构建 canonical projection。同一对象在单次快照内只序列化一次，出现次数仍保存在数组中。

工具批次按 hook 输出中的 assistant toolCall 及其后对应 toolResult 关联。一个 assistant 的多个调用属于同一批次。任何成员需要保留时，该批次在 hook 输出中的所有成员均保留。摘要插入批次之外。合法输入不会经筛选变成孤立输出，不替第三方 hook 修复它自身已经删除或倒置的依赖。

容量 fence 继续检查实际编码后的所有保留项。不确定映射可能压缩较少，甚至阻断，但不能借此删去 hook 内容或放宽容量。

throughput checkpoint。本轮一个 owner，依次完成红证据、纯重建逻辑、真实绿证据与受影响回归、局部配对计时、打包和提交。不重启架构竞争，不进入 P3。
