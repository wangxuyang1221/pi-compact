# 会话锁恢复的单写者修复

目标是保持死进程锁的正常恢复，同时确保两个恢复进程不能同时成为会话写入者。

数据形状保留 `.lock` 的 `{pid, nonce}`。增加只用于短暂取得所有权过程的 `.lock.claim`，内容同样记录本次 PID 与 nonce。它由 `open('wx')` 原子创建，只有创建者可在同步临界区结束时删除。

方案一是在 unlink 前再次读取 PID 或 inode。读取与 unlink 仍是两个操作，竞争窗口仍然存在，不能提供排他性。

方案二是所有 claim 在同一个独占 claim 文件下执行检查、删除死锁、建立新锁。并发 contender 无法进入这段操作，因而不会误删刚取得的活锁。选择此方案，不增加 native 依赖，也不改变会话控制器接口。

claim 文件不按 PID 自动回收，否则会再次引入相同的递归竞争。若进程恰好在临界区中被杀，后续启动明确拒绝。只有用户确认所有会话写入者停止后，才能手动移除该会话的 claim 文件。普通运行期间进程死亡只留下 `.lock`，仍可自动恢复。文档与错误必须解释此边界。

已有 owner 的正常释放仍按 nonce 匹配删除自身 `.lock`。其 PID 活着时，其他遵守协议的 claimant 无法替换该锁，因此释放不会删除另一个合法 owner。进程外人工更改锁与跨机器共享文件系统不在保证内。

按 Fix Root Causes 修复所有 claim 的共同临界区；按 Prove It Works 先保留双进程真实 Pi 失败对照，再验证 contender 在恢复中和恢复后均不能请求或写入。
