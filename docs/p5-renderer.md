# Completion divider

The Pi 1.5.2 adapter replaces the collapsed completion card with a centered `↗↙ Context compacted` label and thin rules. It uses the active theme's `dim` and `muted` foreground colors. It adds no background, token count, duration, or model request. At 20 cells the complete label fits without rules. Smaller widths truncate by terminal cells.

`Ctrl+O` expands the host's actual text summary. For an opaque checkpoint it shows the committed schema, provider, protocol, covered entry count, wire item count, and stored wire byte count. It does not show account identifiers, endpoint, arbitrary wire contents, or encrypted contents. It states that no readable summary is stored. These details do not summarize the conversation. Expansion reads memory without writing the session log or calling a model. After a successful migration the new text checkpoint shows the actual migration result.

The adapter imports `InteractiveMode` and `CompactionSummaryMessageComponent` from the package root supplied by Pi's ordinary loader. It checks the supported version and the running component's class identity. Only components created for sessions loading this extension receive an instance render wrapper. The committed entry is selected by the host message ID when available, otherwise by the most recent matching summary and token boundary on the active branch. Pi creates a new display timestamp at completion, so it cannot identify the committed entry.

Reload, shutdown, and disposal deactivate the session's wrappers. Restoration checks function identity before changing a descriptor, so a later third-party wrapper remains installed. Symlink entrypoints resolve to the same product identity. An incompatible UI keeps the native card and reports a visual downgrade in stderr and the TUI status. UI capability loss does not change the safety adapter or request admission.

Run `pnpm verify:p5-development` for native baseline, manual, automatic, theme, resize, text details, reload, disable, coexistence, failure, and cancellation fixtures. Run `node scripts/verify-p5-integrated.mjs` for remote details, disk restore, fallback, double failure, cancellation, failed persistence, and migration. `node --import=./scripts/fixture/relative-socket.mjs scripts/verify-p5-lifecycle.mjs lifecycle final-dispose` checks multiple SDK sessions, re-enabling, peer wrappers, retained closures, and actual SDK disposal.

Run `pnpm verify:perf --pr P5` for alternating host component measurements. `pnpm verify:p5-package` loads an unpacked tarball through the ordinary loader and separately injects UI capability loss. `pnpm record:p5-demo` creates a terminal recording. Use the relative-socket preload when invoking older runners from a deep worktree path.

The runners use the installed Pi launcher, synthetic history, isolated agent directories, fixture credentials, and a preload that blocks real sockets. The observers inject fixture transport, record terminal writes, and drive isolated UI probes. They do not replace compaction, persistence, request admission, or disposal. PNG and MP4 files render actual tmux ANSI captures with Menlo 16. They are not operating-system screenshots. Real provider reliability and summary quality remain outside this fixture evidence. Independent review and user visual review remain required.
